# Задание 5. Проектирование GraphQL API

В исходной схеме у нас 3 эндпоинта:

- GET `/clients/{id}` - получает клиента по ИД.
- GET `/clients/{id}/documents` - получает документы конкретного клиента.
- GET `/clients/{id}/relatives` - получает список родственников конкретного клиента.

>⚠️ ВАЖНО: это, конечно, просто примитивный тренажер, но тут прямо напрашивается необходимость
> добавить метод для получения документов родственника.

Итоговая GraphQL схема находится в [schema.graphql](./schema.graphql).

Тут, однако, неясно, почему надо прям городить graphql, когда этот сценарий отлично покроется
использованием OData - еще и сторонних пользователей апи не приедтся радовать 
переездом на совсем другую технологию доступа к данным.
